# 手工验证：纯SQLite采集上传

当前C#默认只展示采集状态，扫码入站在Java线边页面完成。完整交接见根目录 `ELECTRIC_CHECK_SCAN.md`。原扫码/FIFO/一分钟静默自动出站流程已经停用，不能作为本版本的验收步骤。

1. 在本目录新建独立测试库 `electric-check-selftest.db`，使用 `01-create-source.sql` 创建空表。不要覆盖生产SQLite或使用生产设备号。
2. 打开C#“设置”，输入维护密码 `lyc3191`，配置测试设备号、测试服务端和独立SQLite文件，启用自动同步后返回采集状态。
3. 使用SQLite管理工具向独立测试库执行 `02-insert-results.sql`，观察最近上传和采集状态。C#也提供受维护密码保护的SQL工具，仅在核对测试库后使用。
4. 服务端应收到 `/openapi/electric-check/records:batch` 的原始明细，设备号与源rowid正确；源库不被采集器修改，上传SN为空，等待同事实现后续结果绑定。
5. 暂停测试服务，继续向测试SQLite追加数据，确认显示错误；恢复测试服务后应重试上传成功。重启C#后继续原上传游标，不应重复正常已确认数据。
6. 默认页无SN输入、入站及出站按钮；后台和托盘不得调用扫码/完成接口。关闭窗体后托盘继续采集，恢复窗体后维护重新锁定；设置、SQL、手工重传及退出受到密码保护。

本轮不验收自动SN绑定、自动出站或出站发送。不要执行旧FIFO升级脚本，不要清空旧扫码缓存。若重建测试SQLite导致rowid归零，请使用新的测试设备号，避免与服务端旧明细身份冲突。以上步骤需在隔离测试服务执行；自动Checks无需连接外部服务。
